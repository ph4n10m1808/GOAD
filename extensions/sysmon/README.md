# Sysmon extension

This agent-only extension installs Microsoft Sysinternals Sysmon on every Windows machine in the `domain` inventory group. It uses the [SwiftOnSecurity sysmon-config](https://github.com/SwiftOnSecurity/sysmon-config) pinned to commit `1836897f12fbd6a0a473665ef6abc34a6b497e31`.

No VM is added, so the extension works with every GOAD provider, including libvirt.

## Install

From the GOAD console:

```text
install_extension sysmon
```

The role is idempotent: it installs Sysmon when absent and reapplies the configuration only when the downloaded, checksum-verified config changes. The Sysmon binary is also checked for a valid Microsoft Authenticode signature before installation.

## ELK monitoring

Install the Sysmon extension before ELK:

```text
install_extension sysmon
install_extension elk
```

The existing ELK Winlogbeat configuration already collects `Microsoft-Windows-Sysmon/Operational`. ELK no longer owns the Sysmon installation, preventing it from overwriting the standalone extension config.

## Splunk Universal Forwarder monitoring

Copy `examples/splunk/inputs.conf` into a Splunk application on each Universal Forwarder. Configure `outputs.conf` separately with the address of your Splunk receiver. The example emits XML events with the sourcetype commonly used for the Sysmon Operational channel.

## Remove

From the GOAD console:

```text
uninstall_extension sysmon
```

The uninstall playbook removes the service, driver, and installation directory. Windows Event Log data already generated by Sysmon is not explicitly cleared.
